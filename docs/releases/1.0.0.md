# Alice 1.0.0 Release Notes

**Secure as Rust, fast as C, parallel as Bend, easy as Ruby.**

Alice 1.0.0 delivers production-ready systems programming with memory safety, C-level performance, effortless parallelism, and Ruby syntax. Build high-performance services, CLI tools, games, and data pipelines with the productivity of a scripting language and the speed of compiled systems code.

## What is Alice 1.0?

Alice is a Ruby-like language that compiles to .NET, designed for developers who want Ruby ergonomics with systems-level performance and safety:

- **Memory safe without a runtime GC pause**: Affine arena allocation for tree structures (2-6x faster than GC, 2-8x lower memory)
- **Fast by default**: Matches or beats idiomatic C# on benchmarks; explicit control where you need it
- **Effortlessly parallel**: Automatic fork/join, data-parallel loops, and structured concurrency
- **Proven correct**: SMT-backed proofs with independently verifiable certificates
- **Full .NET interop**: Call any .NET library, use ASP.NET Core, Entity Framework, Avalonia

## 1.0 Pillars

### Affine Arenas: Memory Safety Without GC Pauses
Tree structures compile to cache-friendly slot-based arenas with compile-time move tracking. **tree-radix 1.3x faster** than GC records with **4x less memory** (401 MB vs 1649 MB, benchmarks/bend2/results/arena.md).

### Direct IL Backend
Compile to IL without Roslyn: **30% faster compile times** on large files, smaller assemblies, deterministic output. IL backend reaches **98% of C# performance** on serial benchmarks (benchmarks/bend2/results/il-vs-csharp.md).

### Checkable Proof Certificates (ADR 0042)
`alice prove --smt` produces independently verifiable LRAT certificates. The standalone `alice-check` tool (<600 lines, no compiler dependencies) validates: SAT proof, bit-blast derivation, and hashes. **Trusted base reduced to rule translation + alice-check** vs. Z3 + compiler + runtime for enumeration.

### Alice Core: Ruby Semantics, C Performance
Own implementations of regex, JSON, CSV, TOML with Ruby semantics and zero-copy parsing:
- **Regex**: 7.2x faster than .NET on regex-redux (551 ms vs 3981 ms UTF-8, benchmarks/core/regex/results.md)
- **JSON**: 3.4x faster DOM building (2.56 GB/s vs JsonDocument, benchmarks/core/json/results.md)
- **CSV**: 1.6 GB/s RFC 4180 parsing with zero-copy fields

### WebAssembly  
Compile Alice programs to wasm32-wasi standalone modules. Run on Node.js, Wasmtime, or any WASI runtime.

### CM Loops: Data-Parallel Primitives
Counted loops that match scan/histogram/permutation shapes compile to `Alice.Runtime.Cm` parallel kernels. **terrain 2.1x faster** than serial on 32 cores (benchmarks/bend2/results/cm.md).

## Upgrade from 0.14.x

### Breaking Changes

1. **Regex semantics changed to Ruby/Onigmo**:
   - Literals are now `Alice.Core.Text.Regex` with Ruby semantics
   - `m` modifier = dot-all, `^ $` are line anchors, `\w` is ASCII
   - Update: Explicit `.NET` regex if you need BCL semantics

2. **Affine arena analysis**:
   - Sum types may compile to arenas automatically (use `affine enum` to require it)
   - New errors AL0240-AL0243 for use-after-move, escapes
   - Update: Mark intended arena types `affine enum`, or allow records

3. **Wrapping operators fixed (ADR 0013)**:
   - `1 &* (b * c)` now correctly wraps only the outer multiply
   - Update: Review wrapping arithmetic if you have `&+` / `&*` with checked subexpressions

4. **FFI callbacks**:
   - Exceptions in callbacks are now caught and rethrown after the C call returns
   - Update: No change needed, but crashes in callbacks now surface as Alice exceptions

5. **Arena regions per-thread (ADR 0037 amendment)**:
   - `scope` only affects its own thread and forked lanes
   - `Dispose` on wrong thread throws
   - Update: Only affects code manually managing arena regions

6. **AggressiveOptimization policy changed**:
   - Loops that only call helpers no longer get AO
   - Loops over owned arrays keep it
   - Update: Use `ALICE_NO_AO` for A/B testing if performance regresses

See [CHANGELOG.md](../../CHANGELOG.md) for the complete list.

### New Features Available

- `dataflow do` with `source` / `stage` / `sink` for streaming pipelines
- Iterators: methods returning `IEnumerable(T)` with `yield` are generators
- `cm for` / `cm ordered for` for data-parallel primitives
- Native callbacks: `Callback(A, B, R)` parameters for zero-allocation C callbacks
- `alice run` image caching: 0.13s startup vs 1.2s for unchanged programs
- IL backend: `--backend il` for direct IL emission (opt-in, C# remains default)

## Known Limitations

See [docs/production.md](../production.md) for the complete list. Notable 1.0 limits:

- **IL backend not default**: Generic method inference needed (Simd.Dot example); C# backend remains default
- **Archives SHA-256 only**: No code signing or macOS notarization at 1.0 (planned for 1.1+)
- **Performance gaps**:
  - IL backend: arena tree benchmarks 6-8% slower than C#
  - Regex: some Unicode patterns 87-92% of .NET Compiled speed
  - Compile-time regex deferred to 1.1
- **Cross-assembly sum types**: `case` destructuring of variants from other assemblies needs workaround
- **ASP.NET lambda parameters**: Use method groups for route binding

## Production Checklist

Ready for production when:
- ✓ You need C-level performance with Ruby syntax
- ✓ Memory safety without GC pauses matters (tree structures, low-latency)
- ✓ .NET interop is a requirement (ASP.NET, EF Core, Avalonia)
- ✓ You want provable correctness for critical logic

Not yet ready when:
- ✗ You need mature cross-language package ecosystem (use .NET packages directly)
- ✗ You require battle-tested production deployments (1.0 is the first stable)
- ✗ You need Windows/macOS code signing for distribution
